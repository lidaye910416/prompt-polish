# 模式1：润色成 /goal 完成条件

## 这个模式在做什么

`/goal <condition>` 收的是**完成条件**，不是任务指令。设置后每轮结束会有一个独立 evaluator 读**对话 transcript**（不跑命令、不读文件）判定条件是否满足。

所以产物不是「一份更好的提示词」，是**一份 transcript 检查清单**：

- 每条判据都要写成 evaluator 能主动引用来判「没做到」的具体对象
- 主模型改完必须把验收命令的**原始输出逐字贴进对话**——否则 evaluator 读不到任何可引用证据，一律返回 `insufficient evidence in transcript`，一路空转到 `goal_check_capped`
- 硬上限 4000 字符；不写轮次上限的话没有其他出口，一轮小误会烧几小时

## 1. 取原文（三路，依次尝试）

1. 有参数 → 直接用参数（`$ARGUMENTS` 逐字保留换行、引号、反引号）
2. 无参数但输入以 `@` 开头 → `cat` 该路径
3. 都没有 → `pbpaste`

三者皆空则打印用法后退出，**不要 pbcopy**（覆盖空剪贴板是破坏性的）。

## 2. 幂等

产物第一行固定：`<!-- polished-by: prompt-polish mode=goal v1 -->`

输入已含此行 → **不重写、不碰剪贴板**，只输出「已符合 v1 规格，差异如下：」+ 逐条差异。
（唯一例外：已 polish 但规范化后 >4000 字符 → 只做精简，回复「已 polish，仅精简 M 字，未改语义」。）

## 3. 语言镜像

输出语言 = 输入语言。中文进中文出，英文进英文出，中英混合以需求句主体语言为准。

## 4. 改写规则

- **保留用户原话里的每一条祈使/否定句**（要/必须/不要/禁止/先…再…/别/未经允许不要），**逐字搬运，不改写语气**。这是重写时最容易蒸发的东西。
- **不发明用户没提的需求。** 唯一合法的四种填空：目标文件路径 / 技术栈 / 测试命令 / 验收阈值。其余一律进「假设」段。
- **形容词 → 可观察动作。** 黑名单命中即替换：`优化 完善 改进 提升 更好 合理 优雅 高效 简洁 干净 清晰 健壮 稳定 成熟 最佳 完美 流畅 全面 彻底 深入 系统性地 梳理 治理 收敛 尽量 尽可能 适当 酌情 视情况 建议 尝试 探索` / `clean elegant idiomatic robust scalable optimal better properly correctly thoroughly polished comprehensive sensible reasonable appropriate seamless`
- **不可判定绝对式**（`零告警 完全没有输出 绝对无 100% 覆盖`）→ 一律改写成可数形式（`grep -c 'console\.' src/` 输出为 0）。
- **规模自适应**：输入 ≤30 字且验收 ≤1 条时，模板可以精简（`目标` + `验收` + `完成=` + `上限`），但 `证据格式` 和 `完成=` 永不删。短 prompt 必须产出短 goal。
- 判据不引用行号、版本号这类易漂移的数值（除非用户明确要求），用「文件名 + 符号名 + 行为」表达。

## 5. 输出骨架

六个标签必须各出现且只出现一次，外加一行 `完成=`。

```
<!-- polished-by: prompt-polish mode=goal v1 -->
目标：<一句话终态。动词开头；每个名词带绝对路径/数量/grep 计数/退出码；结尾带一条兼容性承诺>

范围：
1) <一行一步，动宾开头，写清产物落到哪个文件>
2) …

约束：
- 禁止<用户原话里的红线，逐字搬运，不润色>
- 禁止修改任何已有测试的期望值
- 禁止通过删除或跳过测试（skip/xit/xfail）、放宽断言、降低覆盖率或阈值、注释掉报错、删除本任务要求产出的文件、git checkout/stash 回滚来满足本条件；出现任一即视为未完成
- 禁止执行 git push、gh pr merge、rm -rf、发布、发送消息、删数据等对外或不可逆操作，除非本条件明确写出且用户已在对话中确认
- 禁止顺手改动本任务无关的代码；看到无关问题只在对话里提一句，不要动手
- <至少一条路径级禁令：不得改动某目录/某文件>

验收（在 <仓库绝对路径> 下逐条运行；把每条命令与其完整原始输出原样贴进对话，不摘要、不节选）：
1. `<可运行命令>` → 退出码 0 且输出含 `N passed`
2. `<可运行命令>` → 退出码 0 且输出含 `0 failed`
3. `git diff --name-only -- tests/` → 无输出
4. `<可运行命令>` → 退出码 0（连续跑 4 次全绿，排除抖动测试）

证据格式（逐字照抄，禁止改写、截断、翻译、保留 ANSI 颜色码；粘贴前用 NO_COLOR=1 重跑）：
===验收输出=== <该条命令的 stdout+stderr 纯文本原文> exit=0 ===/验收输出===
没有这段输出即视为未完成。代码写完但没跑、没贴不算完成；「已修复」「我认为已解决」
「应该没问题了」「测试通过了」都不构成证据。

完成=【验收】每条命令的结果与标注一致且原始输出已贴进本对话；【约束】中「禁止」类条目
逐条确认未违反；【范围】逐项写「已做/未做 + 证据」，未做的必须写出来。部分完成不算完成。
任一条不满足就继续做，不要停下来汇报进度。若同一判据在通过与失败之间来回翻转，
停止修改并贴出冲突的两个输出与共同根因。

上限：12 轮。遇阻不提问、不等我回复，按影响最小的假设继续并在回复首行写明 `假设：…`。
第 12 轮仍不满足就立即停止一切工具调用，输出「已完成项：编号+证据 / 未完成项：编号+卡在
哪一步+为什么 / 阻塞原因与人工解锁命令」三段后停止，不要继续重试。
```

**删掉什么**：背景/动机（不改变判定结果）、实施步骤与技术选型（计划不是终态）、风险缓解、时间估算、参考链接清单（evaluator 不能 fetch）、独立的「完成定义」段（已被 `验收` + `完成=` 吸收）。

**字符预算**：目标 200 / 范围 600 / 约束 300 / 验收 500 / 证据格式 220 / 完成= 180 / 上限 150。满打满算 ~2150，余量留给用户改写。超 4000 时**拒绝**，不截断（从尾部砍正好砍掉 `完成=` 和 `上限`，evaluator 必然每轮 `not_met`）。

## 6. 假设与拒绝

**≤3 条 material 假设**（material = 猜错会改变 diff 的内容或范围；只影响措辞的不算），写在产物的「约束」段末尾，每条带「若错 → 后果」，让用户 3 秒可驳回。**>3 条**则不发成品，改用 AskUserQuestion 提 ≤3 个问题。

**推不出检查时**（输入 1–20 字，如「修一下那个 bug」）：**默认照润不追问**——要求贴输出，猜错的检查跑不出输出，evaluator 在 transcript 里看得见，模型下一轮会自己换命令，这是自愈的。但必须显式化假设，并把可运行性兜底写进验收段：

> 现状：先读 <用户给的路径> 确认真实代码结构，把确认结果写进对话再动手；不要凭猜测改文件。
>
> 若上述验收命令在当前环境跑不通（缺凭据、断网、服务未启动、缺依赖），不得判为「不可完成」：先执行并贴出依赖安装 / 构建 / 环境探测的真实输出，再改用离线可执行的等价检查，并把替代命令与理由一并贴出。禁止以「无法执行」「环境不行」作为结束理由。

**输入根本不是任务**（空、纯提问、「你好」）→ 原文照抄，不生成任何 `/goal` 串，**不 pbcopy**：

> 这不是一个可执行的任务，无法生成 /goal 条件。/goal 的判定器只看对话里有没有出现能引用的证据，它判断不了「好不好」「够不够」，会一直判成未达成然后反复续跑。
> 请补三样：①要改的文件或目录（绝对路径）②一条能判定成败的命令（如 npm test / pytest / tsc --noEmit）③不允许改动的范围。
> 补齐后再运行 /prompt-polish:goal。

**输入含不可逆操作**（push / merge / rm / 发布 / 删数据）→ 不拒绝，改写成四步门控（dry-run 清单 → 备份并贴出备份输出 → 执行 → 复核并贴出前后计数），强制加不可逆禁令，回复首行加：

> ⚠ 本条件含不可逆操作，已加入禁止条款并改为「备份成功才执行」。请确认后再粘贴。

## 7. 校验并复制（顺序不可颠倒）

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/check.py <<< "$POLISHED" && pbcopy <<< "$POLISHED"
```

`${CLAUDE_PLUGIN_ROOT}` 在 SKILL.md 正文和 `allowed-tools` 里都会展开（官方文档明载），所以这条不需要用户批准，而且不依赖插件装在哪。

`check.py` 从 stdin 读产物，规范化口径跟 `/goal` 一致（CRLF→LF、逐行 rstrip、tab 展开为 8 列、首尾 trim），然后检查：六个标签各一次、`完成=` 一次、验收每条带 `→` 标注、范围非空、上限是数字、必含 `贴`/`exit=`/`禁止`、反引号外无禁用词、无占位符。

- **exit 0** → 已 pbcopy
- **exit 1 / exit 2** → **没有复制**。把 stderr 的中文原样转述给用户，并说明卡在哪一条

## 8. 回复格式

只回一行，不要复述全文：

```
已复制 N 字到剪贴板。粘到 /goal 后面回车即可。
```

校验失败时：

```
未复制。check.py 拒绝：
<stderr 原文>
```
